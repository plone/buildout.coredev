Handle fieldset fields in the content rules control panel (#2056)

* Handle fieldset fields in the content rules control panel

The edit and add forms of content rule conditions and actions are not
group forms, so plone.autoform puts fields declared in a non-default
fieldset on form.groups instead of form.fields. Getting, adding and
updating a condition or action therefore ignored those fields, even
though @schema listed them.

Merge the fields of all fieldsets into the form fields before reading
or applying values.

Closes #2016

* Refactor the content rules control panel adapter

Split add, get, update and delete into small dispatchers on the URL
path segments, with private helpers for each operation. Share the
CSRF protection, element lookup and edit form setup between them.

Also add type hints and reST docstrings, raise NotFound when the
add view of a rule or element cannot be found, and use f-strings for
error messages. The API responses are unchanged.

* Annotate the rule add view as a Five BrowserView

plone.z3cform is not a declared dependency, and z3c.dependencychecker
also scans imports guarded by TYPE_CHECKING. FormWrapper subclasses
Products.Five's BrowserView, which Zope provides.
