Answer 400 for a non-integer limit on @users (#2046)

* Answer 400 for a non-integer limit on @users

@users parsed its limit with a bare int(), so a value that is not an
integer raised ValueError and the request became a 500:

    GET /@users?query=noam&amp;limit=abc   -&gt;  500
    GET /@users?query=noam&amp;limit=1.5   -&gt;  500

Every other service parses integer parameters with parse_int, which
answers 400 with "Invalid &lt;name&gt;: Not an integer" -- including
querystring-search, which reads a limit of its own. This is the one place
that did not.

parse_qs hands back a list per key, so the value is unwrapped before
parse_int sees it.

Values that already worked are unchanged: limit=1, an empty limit and a
negative limit all still return 200.
