Share schema and value conversion helpers (#2071)

* Add an acceptance backend server for frontend tests

* Share schema and value conversion helpers

Control panels, content rules and new settings services all build JSON
schemas and convert values for plain zope.schema interfaces. Move that
logic to plone.restapi.types.utils:

- SchemaValues, a transient context providing IDexterityContent that
  replaces the three FakeDXContext copies (kept as an alias).
- get_jsonschema_for_schema, which also marks read-only and display
  fields as readOnly and leaves them out of required.
- serialize_schema_values and deserialize_schema_values, with a strict
  mode that reports unknown, read-only and missing fields and checks
  invariants against the merged current values.

Control panels and content rules now use them, with unchanged output.

Also describe and convert schema.Object fields that are not files or
images: no File factory, plain property names, required fields, and
JSON object values, including in lists.

* Reject non-boolean values for Bool fields

Strings other than "true" and "false" used to become False silently,
and numbers were stored as they were.

* Drop the Object field value converters

Fields such as collective.z3cform.datagridfield's DictRow subclass
schema.Object but store plain dicts, and the new collection branch
failed to serialize them. Content Object fields would also have stored
SchemaValues instances. Keep the JSON schema fix for Object fields only.

* Address review: private helpers, BBB aliases, news

- Prefix the shared schema helpers with an underscore, as they are not
  public API, and add type annotations.
- Define the FakeDXContext BBB aliases by assignment instead of a noqa
  import.
- Split the Bool fix into its own news entry.
- Test that control panel updates keep omitted fields and report
  invariant errors once.

* add a few more test cases for the bool deserializer

* edit release notes
