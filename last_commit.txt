Drop metadata_fields from the catalog query (#2045)

* Drop metadata_fields from the query before it reaches the catalog

@search hands the whole request dict to catalog.searchResults(), so
control parameters that are not catalog indexes go with it.
metadata_fields is one: it is read from request.form (or the JSON body)
by the summary serializer, never from the query dict, and every request
from Volto's ObjectBrowserWidget carries it.

ZCatalogCompatibleQueryAdapter already had a name for this class of key,
ignore_query_params, but it only used it to suppress the "No such index"
warning -- the key was still left in the query it returned. ZCatalog
ignores unknown keys, which is why nothing broke in stock Plone; a
catalog that validates its query instead of ignoring what it does not
recognise rejects it.

Pop the ignore_query_params keys at the top of __call__ so the attribute
does what its name says, which also makes the guard further down
redundant.

Checked before changing anything that metadata_fields is not read back
from this dict: services/search/get.py passes request.form.copy(), and
SummaryJSONSerializer.metadata_fields() reads request.form or re-parses
request["BODY"] itself, so dropping it here cannot affect the returned
metadata. The three existing end-to-end tests for partial, full and
fullobjects metadata retrieval confirm it.

zope-testrunner --all on Plone 6.2.1 / Python 3.13, TZ=UTC: 1408 tests,
0 failures, 0 errors, 13 skipped with the fix, against 1406 on main.
Reverting only search/query.py and keeping the two new tests gives 1408
tests, 2 failures -- the two new tests and nothing else.

Note for anyone reproducing: two tests, test_date_index_query and
test_full_metadata_retrieval, fail on an unpatched checkout when the
machine is not on UTC. They compare rendered timestamps against fixed
UTC strings. Run with TZ=UTC.
