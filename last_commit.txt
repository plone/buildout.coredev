Export content that has no language (#105)

fix_language read the serialized language with item.get("language", {}). The
default only applies when the key is absent, and content without a language
serializes to "language": null, so the key is there holding None and the
following .get("token", ...) raised AttributeError: 'NoneType' object has no
attribute 'get'. Exporting a site with content in the language independent
folder, such as classic.demo.plone.org, stopped there.

A language of None is now treated the same as a missing language: the item gets
the default-language placeholder, and deciding on a real language is left to
the import, where the parent is known.

Two tests: a case in the existing test_fix_language table, and an export of a
real content item whose language has been set to None, asserting the exported
data.json carries the placeholder.

Measured with pytest and the Plone 6.2-dev constraints: tests/utils and
tests/exporters went from 176 to 178 passing. The whole suite went from 227 to
229 passing with the same 15 failures and 8 errors before and after; those are
pre-existing and come from test ordering, since tests/utils on its own is 101
passing on an unmodified checkout. Reverting only export_helpers.py and keeping
the tests fails exactly the two new cases.
