Skip security tests for `string._re` on Python 3.14.

It does not exist anymore

Up until Python 3.13, the `string` module imported the `re` module and made it available as `_re`.  Some tests check that this cannot be abused.
But in 3.14 this is no longer the case, so you get three test failures like this:

At first I wanted to patch `string` on 3.14 so we still test similar situations:
even if a module is trusted (like `string`), any module/function/class within this module that starts with an underscore must NOT be available in untrusted code.

But we already test this same vulnerability for `random._os`, which is still there on 3.14, so we don't need a hacked up test case.

For the record, this was the patch that I created, to be used in three tests in `test_expressions.py`:

```
from contextlib import contextmanager

@contextmanager
def _patch_string_re():
    """Make sure string._re exists."""
    need_string_patch = not hasattr(string, "_re")
    if need_string_patch:
        string._re = re
    try:
        yield
    finally:
        if need_string_patch:
            del string._re
```
