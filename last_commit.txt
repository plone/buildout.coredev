Stop filestream_range_iterator.read at the end of the range

WSGI servers like waitress wrap the response body in wsgi.file_wrapper
and read it with read(size) instead of iterating it. read() ignored the
end of the requested range, so a range request (e.g. bytes=0-0 on a large
video) read the file from the start of the range to its end. The server
cut the output at Content-Length, but the disk reads and the CPU time were
spent anyway.
