Preserve query parameters in redirect after login

physicalPathFromURL does not handle query strings, so a came_from
URL like /page?foo=bar produced a path ending in "page?foo=bar"
which failed traversal, causing a fallback to the portal root.

Strip query string and fragment before path validation while
preserving the original came_from URL for the final redirect.

Fixes #4201
