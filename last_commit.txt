Support the plate block type for Plate regions (#2092)

* Support the `plate` block type for Plate regions

Plate regions are now stored as `blocks[&lt;region&gt;] = {"@type": "plate", ...}`
(for example `main`). Register the SearchableText indexer and the link
integrity retriever for `plate`, and make the nested blocks visitor handle
both `plate` and the legacy `__somersault__` type. Regions are found by
`@type`, not by key.

`__somersault__` keeps working and is deprecated, to be removed in the next
major version.

Step 1 of https://github.com/plone/aurora/issues/379

Assisted-by: Claude Opus 5.5

* Name the news entry after the pull request

Assisted-by: Claude Opus 5.5

* Provide the `plonerestapi-plate-regions` ZCML feature

Add-ons that registered their own handlers for `"@type": "plate"`, like
kitconcept.plate, can skip them with
`zcml:condition="not-have plonerestapi-plate-regions"`. Registering the
`plate` indexer in both packages is a ZCML conflict.
